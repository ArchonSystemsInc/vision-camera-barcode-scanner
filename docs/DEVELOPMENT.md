# Development and validation

## Environment

This repository is a native library, with no runnable example app, Podfile, or
Gradle wrapper. Use `npx pnpm@9 install --frozen-lockfile` to install dependencies.

Checks:

```sh
npm run specs       # regenerate Swift/Kotlin/C++ bindings after changing Nitro specs
npm run typecheck
npm run lint
npm run prettycheck
npm test
npm run build
npm pack --dry-run
```

The source reference is `../react-native-vision-camera/packages/react-native-vision-camera-barcode-scanner`
(V5.2.3). Detection on Android follows that implementation; the iOS implementation
uses Vision instead of ML Kit. Android unrotates ML Kit output before calling V5's
raw-buffer coordinate converter. iOS requests raw-axis Vision coordinates and
converts its lower-left normalized origin to top-left buffer pixels. Its scanner
receives the frame output and uses `AVCaptureOutput.metadataOutputRectConverted`
to map those pixels into sensor coordinates. Do not use V5's iOS
`Frame.convertFramePointToCameraPoint` here: its matrix is based on orientation
relative to the device target, which can differ from the preview with rotation lock.

## Stockroom integration

Consumer: `../inFlow/online/apps/stockroom-mobile`. Its package uses a **local file
tarball dependency** on this checkout until the V5-only release is published. Run
`npm run pack:local` before `yarn install` at the inFlow root; repack and reinstall
after changing the local package. A tarball excludes this repository's development
dependencies and avoids duplicate React/native modules. Replace the file dependency with a published version before CI
or distribution from a checkout without this sibling repository.

Stockroom uses RN 0.81.4 and Worklets 0.7.3. Do not upgrade Worklets to 0.9.x without
also upgrading RN: 0.9.x requires RN 0.83+. V5 removed `minFocusDistance`, so its camera
selection now prefers a physical autofocus rear wide-angle camera.
The V5 package no longer ships the V4 Expo config plugin, so camera permission
declarations now live directly in Stockroom's Expo configuration.

App commands (from the Stockroom directory): `yarn start`, `yarn typecheck`,
`yarn ios`, `yarn android`. Native projects are generated by the app's custom
`prebuild:ios` / `prebuild:android` scripts and merged with `ios-merge` / `android-merge`.
Those scripts use clean prebuild; inspect local native changes before invoking them.
Use `LANG=en_US.UTF-8` for CocoaPods.

## Native acceptance checks

The JS suite validates filtering, callback scheduling, throttling, frame cleanup,
and rotation-triggered delivery using mocked native conversions. It does not prove
native transforms, detector accuracy, or platform linking.

On physical iOS and Android devices, verify:

1. QR/EAN detection in portrait, both landscapes and upside-down; compare highlights
   with the barcode corners. Include a square preview and a tall preview.
2. Cover/contain modes, rear camera and mirrored front camera, and layout changes.
3. All corners inside the camera/ROI emits; any corner outside suppresses detection.
4. `fps: 10`, pause/resume, format/ROI changes, unmount/remount, and detector errors.
5. Rotate with unchanged barcode values: first successful detection updates highlights;
   disappearing codes retain Stockroom's existing one-second timeout.
